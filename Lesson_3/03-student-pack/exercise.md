# Lesson 03 Take-Home Exercise

## Title
First Expo App Workflow and Project Structure Reflection

## Purpose
This exercise reinforces lesson 03 by asking you to document how your first Expo app was created, explain the purpose of the key project files, and describe one code change and one troubleshooting response.

## Before You Start
Use these lesson-03 reference files:
- [project-creation-checklist.md](project-creation-checklist.md)
- [project-structure-reference.md](project-structure-reference.md)
- [troubleshooting-checklist.md](troubleshooting-checklist.md)

Helpful lesson-03 terms:
- **template**: the starting project structure generated by `create-expo-app`
- **entry point**: the first file that defines the app UI for this lesson, `App.js`
- **reload**: the process of updating the running app after you save a code change
- **launch path**: the emulator, simulator, or prepared device workflow used to open the app

## Submission Format
Submit a short Markdown or PDF response. Aim for 1 page total.

## Tasks
### Part 1: Project Workflow Snapshot
Report:
- the exact create command you used
npx create-expo-app@latest lesson03-first-app --template blank@sdk-56
- the project folder name you created
lesson03-first-app
- the launch path you used or attempted
npx expo run:android
- whether your app ran successfully by the end of class
Yes, the app opened successfully on the Android emulator and displayed the saved edit
- whether your project is ready to carry into lesson 04
Yes, the project folder is kept as-is with a known-good App.js state, ready to continue into lesson 04.

### Part 2: Project Structure Explanation
Choose three items from [project-structure-reference.md](project-structure-reference.md).

For each item:
- name the file or folder
- explain its purpose in 1 to 2 sentences
- identify whether students are expected to edit it often, sometimes, or rarely at this stage

App.js — where the visible UI and layout live; any change here shows up directly in the running app. Edited often.

app.json — Expo's project configuration: app name, slug, icon, platform settings. Edited sometimes, but rarely for visible UI changes.

package.json — lists installed dependencies (libraries the project needs) and scripts (terminal shortcuts like npm start). Mostly read, rarely edited directly.

### Part 3: Visible Code Change
Describe one change you made in `App.js`.

I changed the original wording to my onw wording and the changes happened instantaneuosly.

Include:
- what line or section you changed, such as the title text, subtitle text, checklist text, or a style block
- what changed in the running app after you saved
- why this is evidence that your development workflow is working

### Part 4: Troubleshooting Reasoning
Choose one issue from [troubleshooting-checklist.md](troubleshooting-checklist.md).

Explain:
- the likely failing step
- one small troubleshooting action you would try first
- what result would tell you whether that action helped

## Success Criteria
Strong submissions will:
- report the workflow concretely instead of vaguely
- distinguish project creation from app launch
- explain key files in plain language
- connect a code edit to a visible app change
- describe troubleshooting as a step-based process
- show whether the project is in a known-good state for lesson 04

## Optional Extension
Include one screenshot of your app after your code change and label what changed.
