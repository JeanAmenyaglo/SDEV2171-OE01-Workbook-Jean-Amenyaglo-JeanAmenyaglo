# Lesson 08 Work Session Checklist

Use this checklist to decide what to do first and to keep the lesson focused.

## Step 1: Choose your current path
- `build` if styling, navigation, and input already basically work
- `repair` if one of those areas is still partial or blocked

### Path meaning
- `build`: you are trying to complete all three required tasks today
- `repair`: you are trying to restore one weak area first so you can return to the required tasks

## Step 2: Verify your starting point
- run the app
- test one navigation path
- test one input interaction
- confirm at least one styled screen still looks intentional

If one of those fails:
- stop there
- use [recovery-paths.md](recovery-paths.md)
- fix the weakest foundation first

If nothing runs at all:
- stop coding changes
- use [worked-example.md](worked-example.md) with your instructor
- identify the first repair target before returning to this checklist

## Step 3: Complete the required tasks in order
- Task 1: styling cleanup
- Task 2: navigation flow check
- Task 3: input-driven interaction

Do not start the optional challenge until the required tasks are stable.

## Step 4: Recheck success criteria
- open [success-criteria.md](success-criteria.md)
- confirm each required area actually works
- do not assume “I changed code” means “the task is complete”

### Navigation reminder
- “working navigation” means one forward path plus one return path

## Step 5: Record your progress
- open [progress-tracker.md](progress-tracker.md)
- mark which required tasks are complete
- mark which area is still partial or blocked, if any

## Step 6: Prepare for the checkpoint
- if you are on the `build` path, be ready to show the integrated app
- if you are on the `repair` path, be ready to show the repaired area or explain the exact blocker and next repair action
