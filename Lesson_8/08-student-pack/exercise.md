## Assessment rule for today
- if you are on the `build` path, the goal is to complete all three required tasks
- if you are on the `repair` path, the goal is to restore one blocked area first, then return to the required tasks if time allows
- a documented repair path is acceptable as incomplete progress, but it is not the same as a fully complete integrated solution

## Required Task 1: Styling Cleanup
Choose one screen in your current project and improve its readability.

Default file anchor:
- start with `src/app/index.js` unless your instructor directs you elsewhere

Your styling cleanup must include:
- one spacing improvement
- one text hierarchy improvement
- one consistency improvement across repeated sections or surfaces

Evidence of completion:
- the screen is easier to read than before
- you can name the three styling improvements you made

## Required Task 2: Navigation Flow Check
Verify that your project has a clear screen-to-screen flow.

Your navigation task must include:
- one working forward navigation action
- one working return path
- one explanation of which route is the home screen and which route is the second screen

Default file anchors:
- `src/app/_layout.tsx`
- `src/app/index.js`
- `src/app/details.js`

Evidence of completion:
- you can move between screens without breaking the app
- you can explain the route structure clearly

## Required Task 3: Input-Driven Interaction
Verify that your project has one working interaction on a screen.

Your interaction task must include:
- one input field
- one user action such as a button press
- one visible response after the interaction

Default file anchor:
- start with `src/app/details.js`

Evidence of completion:
- the interaction produces a visible change
- you can explain which event handled typing and which event handled the action

## Optional Integration Challenge
Only start this task if all three required tasks are already stable.

Choose one:
- improve the flow between the home screen and the interaction screen
- improve the visual clarity of the response area
- improve the wording of the action and feedback so the interaction is easier to understand

Evidence of completion:
- the app feels more cohesive after the change
- you can explain why the change improved the combined flow

## End-of-Class Checkpoint
Before class ends, be ready to show:
- if you are on the `build` path:
- your current working app
- if you are on the `repair` path:
- the repaired area or one clearly documented blocker and one next action

Also be ready to answer:
- which required task you completed first
- which area still needs the most attention, if any
