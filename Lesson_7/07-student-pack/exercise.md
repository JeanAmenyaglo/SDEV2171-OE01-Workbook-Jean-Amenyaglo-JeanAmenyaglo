# Lesson 07 Take-Home Exercise

## Title
Input and Interaction Review

## Purpose
This exercise reinforces lesson 07 by asking you to explain how your app captures user input and turns it into visible behaviour.

## Before You Start
Use these lesson-07 reference files:
- [interaction-build-checklist.md](interaction-build-checklist.md)
- [input-pattern-reference.md](input-pattern-reference.md)
- [starter-snippets.md](starter-snippets.md)
- [troubleshooting-checklist.md](troubleshooting-checklist.md)

Helpful lesson-07 terms:
- **input**: information entered by the user
- **event**: something the app responds to, such as typing or pressing
- **visible behaviour**: what the screen shows after the interaction happens
- **handler**: the code that responds to an event

## Submission Format
Submit a short Markdown or PDF response. Aim for 1 page total plus one screenshot.

If you used the instructor-guided reference path because your own project was not ready:
- you may still complete this exercise
- clearly state that you used the reference path
- identify which observations, code comparisons, or repairs were your own work
- include one sentence naming the next step for getting your own project ready for lesson 08

## Tasks
### Part 1: Input Capture
Write 4 to 6 sentences explaining:
- which component captured the user input
- which event responded when the text changed
- how the screen used that input later

### Part 2: Press Action
Describe one `Pressable` interaction from your app.

Include:
- where the press target appeared
- what the press was supposed to do
- what visible result showed that it worked

### Part 3: Behaviour Reflection
Describe one visible behaviour on the screen that changed after user interaction.

Include:
- what the user typed or pressed
- what changed on screen
- why that change made the app feel more interactive

### Part 4: Troubleshooting or Recovery Reasoning
Choose one issue from [troubleshooting-checklist.md](troubleshooting-checklist.md).

Explain:
- the likely cause
- one small fix you would try first
- what result would show that the fix worked

## Success Criteria
Strong submissions will:
- use input and event terms accurately at a beginner level
- clearly connect `TextInput`, `Pressable`, and the visible response
- describe one interaction as a step-by-step flow
- explain troubleshooting as a small-step process
- include one required screenshot of the interaction screen
- label the input area and the visible response area with either:
- short text callouts on the image, or
- two short caption lines directly below the image
