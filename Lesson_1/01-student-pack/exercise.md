# Lesson 01 Take-Home Exercise

## Title
Mobile App Landscape and App Analysis

## Purpose
This exercise strengthens the lesson-01 outcomes by asking you to compare mobile-development approaches, analyze a demo app, and suggest an improvement using the language of screens, components, and navigation.

## Before You Start
Use [demo-reference.md](demo-reference.md) as your reference for the in-class demo app. You do not need to run the app for this lesson.

Helpful lesson-01 terms:
- **screen**: one major view in the app
- **component**: a reusable UI piece such as text, a button, a card, or an input
- **navigation**: how the user moves between screens
- **feedback preview**: a visible interface change after a user action

## Submission Format
Submit a short Markdown or PDF response. Aim for 1 to 2 pages total.

## Tasks
### Part 1: Mobile App Approach Comparison
Choose three mobile apps that you use regularly.

For each app:
- describe its main purpose in one or two sentences
- guess whether it is likely native, hybrid, or cross-platform
- explain what clues led you to that guess

It is acceptable to write `uncertain between ...` if you can justify your reasoning with visible clues.

Finish this section by answering:
- Which development approach seems most practical for a small team building a new business app?
- What tradeoff would that team still need to accept?

### Part 2: Demo App Analysis
Using the in-class Expo demo app, document:
- at least three distinct screens or views
- at least five UI components you observed
- the main navigation pattern used in the app
- one example of user feedback in the interface

You may use a table, bullets, or a short diagram.

### Part 3: Feature Improvement Proposal
Propose one realistic new feature for the demo app.

Include:
- a one-sentence user story
- why the feature would be useful
- which screen or screens would need to change
- which components might be added, updated, or reused

### Part 4: Course Readiness Reflection
Write 3 to 4 sentences answering both prompts:
- What is one course expectation, habit, or support process that will matter for your success?
- What is one kind of app you now understand React Native could be used to build?

## Success Criteria
Strong submissions will:
- use correct terminology from lesson 01
- clearly distinguish screens, components, and navigation
- show reasonable thinking about platform tradeoffs
- propose a feature that fits the app instead of inventing a different product
- reflect accurately on course expectations and the kinds of apps covered in lesson 01

## Optional Extension
Sketch the navigation flow for your proposed feature using boxes and arrows.
